# GitHub Release Setup for Genentech/exohub

This document describes the PR-merge-triggered release flow for the public
[Genentech/exohub](https://github.com/Genentech/exohub) repository.

## How releases work

1. `oss-sync --pr` opens a PR on `Genentech/exohub` carrying a bumped `VERSION` file.
2. The repo owner reviews and merges the PR → push to `main`.
3. **`auto-tag.yml`** — detects the new `VERSION` value, creates a `v<version>` tag
   (e.g. `v0.114.0`) using the `RELEASE_TOKEN` PAT and pushes it.
4. **`release.yml`** — triggered by the new tag, builds all six binaries via goreleaser
   and publishes a single GitHub Release containing all archives, per-project checksums,
   and `install.sh`.

After a successful release, the install one-liner works:

```sh
curl -fsSL https://github.com/Genentech/exohub/releases/latest/download/install.sh | sh
```

## Required secret: `RELEASE_TOKEN`

A tag pushed with the default `GITHUB_TOKEN` does **not** trigger other GitHub Actions
workflows (GitHub loop-prevention). To make `auto-tag.yml`'s pushed tag fire
`release.yml`, you must set a repository secret named `RELEASE_TOKEN`.

### Creating the PAT

1. Go to **GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens**.
2. Create a token scoped to the `Genentech/exohub` repository with:
   - **Repository permissions → Contents**: Read and write
3. Copy the token value.

### Adding the secret to the repository

1. Go to **Genentech/exohub → Settings → Secrets and variables → Actions**.
2. Click **New repository secret**.
3. Name: `RELEASE_TOKEN`, Value: the PAT you created above.
4. Click **Add secret**.

Without `RELEASE_TOKEN`, `auto-tag.yml` still creates the tag (using `GITHUB_TOKEN`),
but `release.yml` won't auto-run. In that case, trigger it manually:

```
GitHub → Genentech/exohub → Actions → Release → Run workflow → tag: v<version>
```

## Release artifacts

Each release contains:

| Archive | Description |
|---------|-------------|
| `exo_<version>_<os>_<arch>.tar.gz` | Main `exo` CLI |
| `exo-credential-helper_<version>_<os>_<arch>.tar.gz` | Credential helper |
| `git-annex-remote-drive_<version>_<os>_<arch>.tar.gz` | Google Drive git-annex remote |
| `git-annex-remote-s5cmd_<version>_<os>_<arch>.tar.gz` | S3/s5cmd git-annex remote |
| `git-annex-remote-artifactdb-export_<version>_<os>_<arch>.tar.gz` | ArtifactDB export remote |
| `adb-standalone_<version>_<os>_<arch>.tar.gz` | Standalone ArtifactDB server |
| `<project>_<version>_checksums.txt` | SHA-256 checksums per project |
| `install.sh` | One-liner installer |

Supported platforms: `linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`.

## OSS goreleaser configs

The public tree ships OSS-specific goreleaser configs (`.goreleaser-oss-*.yml`):

- No `internal` build tag (OSS build has no dependency on internal-only libraries)
- No built-in Google Drive client ID/secret injected via ldflags
- Includes `archives:` and `checksum:` sections so goreleaser produces
  distributable tarballs (the internal configs are build-only)

These configs are generated by `scripts/oss-export.sh` from the internal
`.goreleaser-oss-*.yml` source files.

## Triggering a release manually

If you need to re-release an existing tag or trigger a release without a new
VERSION bump:

```sh
# From the Actions tab on GitHub:
# Actions → Release → Run workflow → tag: v0.114.0
```

Or locally using the GitHub CLI:

```sh
gh workflow run release.yml --repo Genentech/exohub --field tag=v0.114.0
```
